# La bibliothèque de design de LEKA

Les guides que le designer de LEKA lit avant de juger un domaine. Chacun tient
en une page et dit trois choses : ce qu'on regarde, ce qu'on attend, comment
on le dit. Les valeurs qu'ils donnent (durées, courbes, seuils) se reprennent
telles quelles dans un constat.

| Guide | À ouvrir quand |
| --- | --- |
| `principes.md` | toute revue : comment juger, le format d'un constat, quand animer |
| `revue-animations.md` | on relit les animations d'un écran ou d'une pull request |
| `audit-mouvement.md` | on passe tout le mouvement d'une application en revue |
| `opportunites-animation.md` | on cherche ce qui gagnerait à bouger, et ce qui ne doit pas |
| `construire-animation.md` | on écrit une animation ou un composant animé |
| `performance-animation.md` | une animation saccade, ou on choisit quoi animer |
| `interfaces-fluides.md` | gestes, glisser, ressorts, matières, typographie fine |
| `pire-des-cas.md` | on éprouve un écran avec des données défavorables |
| `telephone-web.md` | une application web doit se tenir comme une application installée |
| `react-native.md` | l'application est en React Native ou Expo |
| `swift.md` | le code est en Swift ou SwiftUI |
| `notifications-sonner.md` | l'application affiche des notifications avec Sonner |
| `bibliotheques.md` | on choisit une bibliothèque pour un besoin d'interface |
| `directions.md` | on propose plusieurs versions d'un écran à comparer |
| `vocabulaire-mouvement.md` | il faut nommer un effet décrit vaguement |
